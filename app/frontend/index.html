Semantic Search (Stage 7: query embedding -> vectorstore.search())

    
Takes its input from Stage 6's normalized output above. Embedded (bge-m3), then matched against every stored chunk via pgvector cosine similarity. Edit below if needed before searching.

    

      
      
    

    

    

  


  

    
Keyword Search (Stage 8: PostgreSQL full-text search)

    
Takes its input from Stage 6's normalized output above. No embedding call - exact/lexical token matching via tsvector + GIN index. Complementary to Stage 7: strong on exact codes/terms, weak on paraphrases. Edit below if needed before searching.

    

      
      
    

    

    

  


  

    
Hybrid Search (Stage 9: RRF fusion of Stage 7 + Stage 8)

    
Takes its input from Stage 6's normalized output above. Runs semantic (Stage 7) and keyword (Stage 8) search in parallel, then combines both ranked lists via Reciprocal Rank Fusion - no raw-score comparison, just rank position. Edit below if needed before searching.

    

      
      
    

    

    

  


  

    
No-Answer Detection (Stage 10)

    
Checks Stage 9's last result against TWO bars - passes if EITHER clears: RRF score (both sources agree) OR raw similarity (confident even if only one source found it). v1 was RRF-only and had a confirmed 56% false-negative rate on paraphrased questions - see app/eval/eval_set_v1.md. Thresholds are small-sample starting guesses - adjust and re-check freely.

    

      
      
      
      
      
    

    

  


  

    
Context Construction (Stage 11)

    
Prepares Stage 9's surviving chunks for the LLM prompt: dedup exact repeats, merge chunks that are adjacent in the same document into one coherent block, restore document reading order (not RRF rank order), trim to a token budget by dropping lowest-relevance blocks first, then tag each with a citation marker [S1], [S2]...

    

      
      
      
    

    

    

  


  

    
Answer Generation (Stage 12: qwen2.5:7b)

    
Takes its question from Stage 6's normalized output above, plus Stage 11's context blocks. Sends a grounded prompt to the local LLM (Ollama, qwen2.5:7b) and shows the answer. The LLM does not search anything - Stages 6-11 already found the evidence; this stage only writes the answer from it. RAG Eval (Stage 13)

  
Runs a batch of questions through the FULL pipeline (Stages 6-12, including the LLM) and scores retrieval, no-answer detection, and answer quality automatically - instead of eyeballing results one at a time.
